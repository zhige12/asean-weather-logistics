## 四、配置说明（`src/main/resources/application.properties` + `.env.local`）

后端通过 `spring.config.import=optional:file:./.env.local[.properties]` 读取根目录 `.env.local` 环境变量。以下为**脱敏**后的关键项：

| 配置项 | 说明 | 示例值（已脱敏） |
|---|---|---|
| `server.address` | 监听地址，`0.0.0.0` 使手机同 WiFi 可连 | `0.0.0.0` |
| `weather.real.base-url` | 大赛官方 CRA40 实况/预报接口 | `http://<官方地址>:8001` |
| `weather.real.token` | 官方气象接口 Token（**仅存后端**） | `<气象TOKEN>` |
| `weather.source` | 数据源切换：`contest-observation` / `open-meteo` / `simulated` | `contest-observation` |
| `ollama.enabled` | 本地大模型开关（离线演示置 true） | `true` |
| `ollama.model` | 本地模型 | `qwen2.5:14b` |
| `ollama.url` | Ollama OpenAI 兼容端点 | `http://localhost:11434/v1/chat/completions` |
| `deepseek.fallback.key` | 在线 DeepSeek 兜底 Key（可选，联网降级用） | `<DEEPSEEK_KEY>` |
| `tianditu.keys` | 天地图密钥池（**仅存后端**，前端走同源代理） | `<TK1,TK2,...>` |
| `tianditu.cache-dir` | 瓦片磁盘缓存目录 | `data/tile-cache` |
| `decision.cache.dir` | 多智能体预生成缓存目录 | `decision-cache` |
| `osm.loader.enabled` | GraphHopper OSM PBF 加载开关（坐标算路模式） | `false` |

> **合规说明**：气象 Token、天地图密钥、DeepSeek Key 等敏感信息全部只存后端环境变量，前端不持有任何密钥；AI 推理优先走本地 Ollama（数据不出境），仅本地不可用且联网时按 `Ollama → 在线 DeepSeek → 规则模板` 逐级降级。

**`.env.local` 模板（脱敏）：**
```properties
WEATHER_REAL_BASE_URL=http://<官方地址>:8001
WEATHER_REAL_TOKEN=<气象TOKEN>
WEATHER_REAL_OBSERVATION_TIME=202412312000
OLLAMA_ENABLED=true
OLLAMA_MODEL=qwen2.5:14b
TIANDITU_KEYS=<TK1,TK2,TK3,TK4,TK5>
DEEPSEEK_FALLBACK_KEY=<可选>
```

前端环境变量 `frontend/.env.local`（若使用直连天地图时）：`VITE_TIANDITU_TK=<浏览器端TK>`；当前架构走后端同源代理，前端通常无需配置。

## 五、部署与运行步骤

### 5.1 后端服务

```bash
# Windows
gradlew.bat bootRun
# Linux / macOS
./gradlew bootRun
```
- 启动后监听 `http://<本机IP>:8080`，`GET /ping` 返回 `OK` 即成功。
- 启动时自动加载 `resources/data/vietnam-road-network.json` 构建拓扑图（`StartupWarmup` 预热）。

### 5.2 PC 调度大屏 / 司机端（Web）

```bash
cd frontend
npm install
npm run dev          # 开发：Vite 热更新，默认 http://localhost:5173
# 或构建产物（后端会从 file:frontend/dist 托管）：
npm run build        # 输出到 frontend/dist
```
- 大屏入口：`http://<本机IP>:8080/`
- 司机端入口：`http://<本机IP>:8080/driver.html`
> 注意：Spring 静态托管读的是**已构建的 dist**，改前端代码后需 `npm run build` 重新构建；开发调试则用 Vite dev server。

### 5.3 司机端 Android APK（瘦客户端）

```bash
cd frontend
npm run build
npx cap sync android
cd android
gradlew assembleDebug --no-daemon
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```
- `capacitor.config.json` 的 `server.url` 指向**运行后端的电脑局域网 IP**（示例 `http://192.168.200.140:8080/driver.html`）。演示前需把该 IP 改为当前后端机器 IP，手机与电脑连同一 WiFi 即可。
- 瘦客户端机制：APK 运行时 WebView 加载电脑上的 dist，因此前端改动只需重新 `npm run build` + 后端在跑，手机重开 App 即更新，无需重装 APK。

### 5.4 离线演示（拔网线）清单

1. 提前 `ollama pull qwen2.5:14b` 并让 Ollama 随系统启动（`OLLAMA_ENABLED=true`）。
2. 提前拉取一次气象数据 / 或切 `weather.source=simulated`。
3. 提前生成决策缓存：用官方历史数据回放跑三组场景，产出 `decision-cache/*.json`（`scenario_heavy_rain / scenario_light_rain / scenario_dual_risk`）。
4. 天地图瓦片：已两级缓存（内存 + `data/tile-cache` 磁盘），演示前预热热门瓦片。
5. 断网后重复核心流程验证：本地推理、本地算路、本地瓦片全部可用。

## 八、模块结构（`src/main/java/com/example/aseanweatherlogistics`）

- `controller/` 15 个 REST 控制器（接口层）
- `service/` 核心业务：`RouteService`（图计算 + 熔断 Dijkstra）、`WeatherSimulator`（风险注入）、`IntermodalService`/`WaterRiskEngine`/`TributaryRiskService`（水运与陆水联运）、`MultiAgentService`/`RiskAgent`/`SolutionAgent`/`TouchAgent`（三智能体）、`OllamaService`/`DeepseekService`/`AIService`（大模型通道与降级）、`CostCalculator`/`DecisionSandboxService`/`DecisionOrchestrator`/`DecisionLogService`、`RealWeatherService`/`ContestWeatherProvider`/`OpenMeteoWeatherProvider`/`SimulatedWeatherProvider`/`WeatherSourceService`（多源气象）等
- `repository/` `RouteRepository`/`CustomsEfficiencyRepository`/`KnowledgeBaseRepository`（JSON 载入）
- `model/` `dto`/`entity`/`vo`
- `config/` `WebConfig`（静态资源 + 瓦片路径托管）
