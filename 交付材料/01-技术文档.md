**`.env.local` 模板**：仓库根目录已提供可直接复制的脱敏模板 [`.env.example`](../.env.example)（`copy .env.example .env.local`），其中每一项都带“留空会怎样”的注释。手工填写时的最小集合如下：
```properties

WEATHER_REAL_TOKEN=<气象TOKEN>
WEATHER_REAL_OBSERVATION_TIME=202412312000
OLLAMA_ENABLED=true
OLLAMA_MODEL=qwen2.5:14b
```

## 五、部署与运行步骤

> 前提：clone 后先准备 `.env.local`（可直接用根目录 `.env.example` 复制，全部留空也能启动）。
> JDK 不需额外配置：`../gradle.properties` 已启用 toolchain 的 auto-detect / auto-download，**不写死任何开发机的 JDK 绝对路径**；
> 若本机已装多个 JDK 需指定，取消 `org.gradle.java.home` 一行的注释并改为本机路径即可（默认保持注释状态）。

### 5.1 后端服务

```bash
# Windows
gradlew.bat bootRun
# Linux / macOS
./gradlew bootRun
```
- 启动后监听 `http://<本机IP>:8080`，`GET /ping` 返回 `OK` 即成功。
- 启动时自动加载 `resources/data/vietnam-road-network.json` 构建拓扑图（`StartupWarmup` 预热）。

### 5.2 PC 调度大屏 / 司机端（Web）

```bash
cd frontend
npm install
npm run dev          # 开发：Vite 热更新，默认 http://localhost:5173
# 或构建产物（后端会从 file:frontend/dist 托管）：
npm run build        # 输出到 frontend/dist
```
- 大屏入口：`http://<本机IP>:8080/`
- 司机端入口：`http://<本机IP>:8080/driver.html`
> 注意：Spring 静态托管读的是**已构建的 dist**，改前端代码后需 `npm run build` 重新构建；开发调试则用 Vite dev server。

### 5.3 司机端 Android APK（瘦客户端）

```bash
cd frontend
npm run build
npx cap sync android
cd android
gradlew assembleDebug --no-daemon
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```
- `capacitor.config.json` 的 `server.url` 指向**运行后端的电脑局域网 IP**（示例 `http://192.168.200.140:8080/driver.html`）。演示前需把该 IP 改为当前后端机器 IP，手机与电脑连同一 WiFi 即可。
- 瘦客户端机制：APK 运行时 WebView 加载电脑上的 dist，因此前端改动只需重新 `npm run build` + 后端在跑，手机重开 App 即更新，无需重装 APK。

### 5.4 离线演示（拔网线）清单

1. 提前 `ollama pull qwen2.5:14b` 并让 Ollama 随系统启动（`OLLAMA_ENABLED=true`）。
2. 提前拉取一次气象数据 / 或切 `weather.source=simulated`。
3. 提前生成决策缓存：`../tools/pregen_agent_cache.ps1` 按 scenarioId 跑好三组场景，产出 `decision-cache/*.json`（`scenario_heavy_rain / scenario_light_rain / scenario_dual_risk`）与文案池 `recommendation-pool.json`。**在途行程不读缓存**（缓存里的推荐没考虑车的位置）。
4. 天地图瓦片：已两级缓存（内存 + `../data/tile-cache` 磁盘），演示前预热热门瓦片。
5. 断网后重复核心流程验证：本地推理、本地算路、本地瓦片全部可用；界面上的来源/通道徽标应如实变为「模拟降级 / 缓存 / 模板」而不是继续谎称实时。

## 六、API 接口清单

> 共 **19 个控制器 / 96 个端点**（由 `node tools/_api_inventory.mjs` 从 `controller/` 包直接扫描生成，与代码同步）。
> 计数含无路径的根映射（如 `@GetMapping` 不带括号参数的 `GET /api/geocode`、`GET /api/knowledge`）；取证脚本早期版本因正则强制要求 `(` 而漏计这类端点，已修正。
> 统一前缀 `/api`；实时事件走 SSE（`text/event-stream`）。

### 6.1 算路与路线状态 `RouteController`（`/api/routes`，同时兼容别名 `/api/route`）（12）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/plan` | 路径规划（两种入参二选一：`originId+destinationId` 节点模式，或 `startLat/startLng/endLat/endLng` 坐标模式——后者先吸附最近路网节点，超 5 km 报 400「该区域暂未覆盖路网」）；返回 baseline/current/extraHours、风险逐段、`routeGeoJSON`、吸附信息 |
| GET | `/plan-with-weather` | 带气象的方案（AI 已移出关键路径，算路不等模型） |
| GET | `/plan-real` | GraphHopper 坐标算路（`fromLat/fromLon/toLat/toLon`），需 `osm.loader.enabled=true` 且 PBF 已加载 |
| GET | `/candidates` | 多候选路线（推荐 / 备选 / 最快） |
| POST | `/plan-sample` | 样例路径规划（演示固定起终点） |
| POST | `/detour` | 绕行计算（禁用指定风险边的局部重算） |
| GET | `/status` | OSM 加载器状态（`enabled/loading/loaded + message`，对应顶栏「OSM 状态」） |
| POST | `/block`、`/unblock` | 手动熔断 / 解除某条边（`penaltyMultiplier` 默认 100） |
| POST | `/osm/start`、`/osm/stop` | GraphHopper OSM PBF 坐标算路加载开关（**公网演示被护栏直接 403**，它会加载 311 MB PBF） |
| GET | `/network` | 路网拓扑（节点/边，供骨骼图与调试） |

### 6.2 运输任务与在途 `TaskController`（`/api/task`）（5）、`TripController`（`/api/trip`）（4）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/task/dispatch` | 公司派单 → SSE 广播 `task-assigned`（默认剧本：桂A·D12345 / 阿明 / 18 t 冷鲜 / 南宁→河内） |
| GET | `/api/task/current` | 司机端拉取当前任务（SSE 断开时的兜底回到任务模式） |
| POST | `/api/task/accept`、`/api/task/reject` | 司机接单 / 拒单（带原因），回执回流大屏与决策日志 |
| POST | `/api/task/reset` | 演示复位：撤销任务（界面「撤销派单」） |
| POST | `/api/trip/start`、`/api/trip/progress` | 开始行程 / 上报在途进度（司机端约 30 s 一次；超 5 min 视为不在途） |
| GET | `/api/trip/signal`、POST `/api/trip/reset` | 读当前行程信号 / 复位 |

### 6.3 实时事件与三智能体 `AgentController`（`/api/agent`）（4）、`AgentAnalysisController`（1）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/agent/events` | **SSE** 唯一长连接；首帧 `init`，之后推 `route-update` / `task-assigned` / `agent-status` / `outreach-update` / `canal-block`·`canal-recover` |
| POST | `/api/agent/register`、`/api/agent/unregister` | 关注路线注册 / 注销（大屏与司机端各自登记自己在看的路线） |
| GET | `/api/agent/status` | 守护与重算运行状态（不含密钥） |
| GET | `/api/agents/analysis` | 三智能体决策分析（风险研判 / 方案生成 / 触达）+ 通道标签 |

事件与两端的适配关系（逐事件比对后端 `SseEmitter.event().name(...)` 与两端 `addEventListener(...)` 得出）：

| 事件 | 后端广播位置 | 调度大屏 `App.vue` | 司机端 `DriverApp.vue` |
|---|---|---|---|
| `init` | `RouteAgentService` 连接建立时 | 不监听（当前活动起终点由各端自行 `POST /api/agent/register` 确定，不依赖首帧） | 不监听（同上，另有 `GET /api/task/current` 兜底） |
| `route-update` | `RouteAgentService` 风险变化重算后（300 ms 防抖） | ✓ 刷路线与风险着色 | ✓ 刷导航与换线弹窗 |
| `task-assigned` | `TaskController` 派单后 | ✓ 任务卡状态 | ✓ 进任务模式 |
| `agent-status` | `DecisionOrchestrator` 逐智能体点亮 | ✓ 三智能体面板 | — 司机端不展示推理过程，按设计不监听 |
| `outreach-update` | `OutreachService` 分级叫应状态变化 | ✓ 触达进度的时间线 | ✓ 指令弹窗 |

## 八、模块结构（`../src/main/java/com/example/aseanweatherlogistics`）

- **`controller/` 19 个 REST 控制器**（对应第六节 96 个端点）+ `GlobalExceptionHandler`（统一中文错误体）

  - 多源气象：`WeatherSourceService`、`RealWeatherService`（节流+熔断）、`ContestWeatherProvider`/`ContestForecastService`/`OpenMeteoWeatherProvider`/`SimulatedWeatherProvider`、`WeatherWatchdogService`（`@Scheduled` 60 s 守护）
  - 三智能体：**`DecisionOrchestrator`（真正的编排入口：串行调度 + 预生成缓存 + `agent-status` 广播 + 通道标签汇总）**、`RiskAgent`/`SolutionAgent`/`TouchAgent`、`RecommendationPool`（历史文案池轮换）
  - 大模型通道：`OllamaService`（本地）/`DeepseekService`（在线）/`AIService`（预警文案与降级）、`AgentJson`（输出解析）
  - 代价与方案：`CostCalculator`、`IntermodalService`、`DemoConfigService`（企业画像/阈值档）、`StartupWarmup`

  - 业务支撑：`TaskService`（NONE/DISPATCHED/ACCEPTED/REJECTED）、`TripSignalService`（在途进度与新鲜度）、`DecisionSandboxService`（沙盘状态机与方向判定）、`DecisionLogService`（留痕）、`OutreachService`（分级叫应）、`CustomsEfficiencyService`、`KnowledgeBaseService`、`GeocodeService`、`BriefingService`

三条结论：

1. **主流程不需要任何凭证与外网**：路网拓扑、地名库、知识库、瓦片缓存、决策预生成缓存均随仓库或交付包分发，断网机器上算路、风险判定、禁航、分级叫应、司机端触达链路可完整跑通。
2. **需要联网才能核验的是“数据来源真实性”**：官方气象需 Token 与组委会侧网络，天地图需密钥与授权白名单，越南街道兜底需代理。三者不可达时界面显示降级后的真实来源，不做伪装。
3. **完全离线演示请直接用 `../asean-demo` 交付包**（内嵌 JRE + 2.9 万张预热瓦片 + 决策缓存；包内 `.env.local` 为便于开箱即可核验而内含申请人本人凭证，边界见 10.3），双击 `start.bat` 即可，不需要装 JDK / Gradle / Node。

### 11.2 环境差异与已知坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 编译报找不到符号 `CorridorAdvisoryService` / `RecommendationPool` | 新增源文件未随提交入库 | 确认 `src/main/java/.../service/` 下这两个类与 `../frontend/src/utils/corridorAdvisory.js`、`src/test/.../SolutionAgentDetourTriggerTest.java` 均在提交物内 |
| `Unsupported class file major version` / toolchain 报错 | 本机 JDK 低于 21 | 装 JDK 21+，或让 toolchain 自动下载（`../gradle.properties` 已开 auto-download） |
| 页面改了但没变化 | Spring 托管的是已构建的 `../frontend/dist` | 重新 `npm run build`，浏览器 Ctrl+F5 |
| 8080 被占用 | 端口冲突 | `gradlew.bat bootRun --args='--server.port=8090'`；离线包 `start.bat` 会自动在 8080–8089 找空端口 |
| 底图全空 | 既无密钥也无预热瓦片 | 属预期降级；需离线出图请填 `TIANDITU_KEYS` 或直接使用 `../asean-demo` 包 |
| 越南街道搜不到 | Nominatim 需出国际公网 | 填 `GEOCODE_NOMINATIM_PROXY`，或置 `GEOCODE_NOMINATIM_ENABLED=false` |
| 写接口返回 429 | 公网演示护栏限流 | 属设计行为；单人演示机可上调 `DEMO_GUARD_STRICT_LIMIT` / `NORMAL_LIMIT` |
| 点击普遍变慢 | 内存热缓存过大导致小内存机器频繁换页 | 调小 `tianditu.mem-cache-entries`（离线包已设 5000） |
| Android 端白屏 | `server.url` 指向的电脑 IP 变了，或手机与电脑不在同一 WiFi | 改 `../frontend/capacitor.config.json` 后 `npx cap sync android` 重装；或直接用手机浏览器打开 `/driver.html` |
