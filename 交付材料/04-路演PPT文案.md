---
**P1 封面**
- 面向东盟跨境物流的突发气象预警与多路线协同调度平台
- ——平陆运河时代陆水联运双向决策引擎
- 参赛组别：智能应用类
- 讲稿：一句话定位——"预警不止于提示，风险导向可执行决策"。

**P2 痛点（一句话钩子）**
- 运河通了，但"预警之后怎么办"没人管
- 四大断层：预警—决策断层 / 陆水信息孤岛 / 跨境链路堵点 / 数据合规困境
- 讲稿：引用调度员原话"最怕的不是没预警，是预警来了我要花半小时拼信息，等拼完最佳绕行窗口已经过了"。

**P3 调研背书**
- 三维田野调查：12 名调度员深访 + 86 名中国司机 + 32 名越南司机 + 口岸/船闸/沿岸百姓
- 越南籍成员母语校验（非机翻）
- 讲稿：所有功能都来自一线真实困境，不是纸面推演。

**P4 核心创新：公—水动态边权共生决策模型**
- 一套图计算内核，公路边 + 水运边共享边权
- 阶跃式惩罚 = 逻辑熔断；双向互备
- 讲稿：强调"不是公路模块+水运模块两套系统"。

**P5 系统架构（放架构图）**
- 主图用 `09-系统架构图-分层版.png`（分层泳道）：接入展现 / 通讯护栏 / **①气象数据接入** / **②风险引擎** / **③AI 智能体** / **④调度执行** / 数据底座
- 讲稿顺序跟着圈号走：气象数据从大赛官方接口进来① → 雨量直接改写路段可通行性② → 引擎给边界、大模型只给文字③ → 最后落到换线绕行、改走水运、停驶等待、分级叫应④
- 需要“气象→动作”四段横向因果链特写时，改用 `08-系统架构图.png`
- 技术标签（图上不写，放讲稿或角标）：Spring Boot、Vue3+Capacitor、GraphHopper/JGraphT 剩余图重算、本地大模型→内网网关→在线大模型→规则模板逐级兜底
- 讲稿：一图讲清全貌；重点说“①与③都可当场核验”（数据源与 AI 通道均如实标注），而不是只讲我们做了什么。

**P6 技术亮点①：动态边权熔断引擎**
- 12h累计降雨>80mm → penalty=100 硬熔断（阈值随风险画像可调 80/100/120mm）；泥石流>0.7 → 1000 切断；运河能见度<1000m 禁航
- 全线熔断时降级兜底，永不"无路可走报错停摆"
- 讲稿：毫秒级重算。

**P7 技术亮点②：三智能体 + 本地私有化**
- RiskAgent→SolutionAgent→TouchAgent 串行
- Ollama 本地部署，数据不出境（降级链兜底）
- 六维对比：耗时/风险/货损/油耗/费用/碳排放
- 讲稿：AI 干到 90%，人做最后 10%。

**P8 技术亮点③：分级叫应闭环**
- 黄/橙/红三级，渠道逐级增强，未确认自动升级上报
- SSE 实时推送 + 确认回执留痕
- 讲稿：指令"发了"不等于"收到"。

**P9 产品形态**
- PC 调度大屏 / 移动端司机 App / 公众模式 / 开放配置平台
- 讲稿：B 端核心 + C 端引流 + 千企千面。

**P10 案例实证（现场 Demo 引子）**
- 案例一：火龙果冷链暴雨熔断 → 切陆水联运
- 案例二：运河能见度禁航 → 反向切回公路
- 讲稿：接演示视频/现场操作。

**P11 离线能力（差异化杀手锏）**
- 拔网线全流程照常：本地推理 + 数据预缓存 + 本地算路 + 磁盘瓦片
- 讲稿：现场拔网线演示。

**P12 商业模式**
- B 端订阅 300—500 元/车·月 + AI 调用 + API 输出；C 端免费引流

**P13 价值与规划**

- 讲稿：面向中南半岛多式联运。
