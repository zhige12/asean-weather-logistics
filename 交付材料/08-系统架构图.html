两条判据链路（不要混为一谈）

实时联动：逐边取两端较差天气，小时雨强 ≥ 50mm/h → 惩罚 100，≥ 20 → 20；风速 ≥ 60km/h → 50；能见度 < 100m → 50、< 500m → 20；气温 ≥ 35℃ → 8。官方预报/沙盘：口岸断面取未来 6h 累计降雨达阈值即注入 penalty=100。惩罚系数 ≥ 100 即判定该边"等效道路中断"

阈值随企业风险容忍度浮动（改动即重估）

保守 80mm平衡 100mm激进 120mm

仅适用于友谊关断面的预报档；芒街固定 70mm。熔断后需降到阈值 − 5mm 以下方恢复（滞后线，防来回翻）；降雨 50mm 只作"关注"叙事，不注入软惩罚

三个智能体顺序接力

风险研判（为什么封友谊关而不封芒街）→ 方案生成（对可比方案集做取舍建议）→ 协同触达（按角色出双语文案）

知识库提供依据，抑制无根据表述

通航安全规定 / 跨境物流规范 / 企业作业规则，按标题 / 关键词 / 正文加权匹配，命中条目注入上下文

推理通道逐级兜底，且如实回报

本地大模型 → 企业内网网关 → 在线大模型 → 规则模板；结果面板标签显示本次真正走了哪一档，断网重试即变"规则模板"

任一通道不可用都不断流程

只影响文字表述，数值结果与推荐方案不变；预生成文案仅在"缓存模式"出现并单独标注

创新点

改走水运 / 反向回公路

车辆滚装上船经平陆运河转海运出境；运河禁航时反向给出公路方案

原地等待 · 延迟发车

公路与水运同时受阻时不强推绕行；司机端进入停驶待命，条件恢复后一键复驶

行驶进度闸门：砍掉做不到的方案

已越过装货港的车不再被推荐"回港口坐船"，避免给出看起来最优却已无法执行的建议

分级叫应到五类人 ＋ 回执闭环

调度员 / 货车司机 / 越南司机 / 船东船员 / 沿岸百姓，中越双语播报；未确认自动升级触达渠道

读图要点　横向四段即本项目的因果主张：气象观测量被直接转换为路径可通行性（第②段），大模型只承担文字、数字全部由确定性引擎产出（第③段），因此第④段的每一个动作都能回溯到具体雨量与阈值、可现场复算。水运不作为并列第二主线，只在公路受阻时被触发评估，故以虚线框表示。本图只划分职责与数据流向，不体现具体框架选型；接口清单见《01-技术文档》，带技术标注的展开版与数据溯源表见《02-系统架构与数据使用说明》。
