①气象数据接入层数据从哪来 · 三源可切换 · 频度合规

大赛官方气象接口（默认主源）

CRA40 实况与预报格点，凭组委会令牌回源；令牌只存服务端环境变量，不进仓库、不进前端产物。界面标签原文：「比赛官方接口（CRA40 实况）」

公开气象服务（备源比对）

免令牌，与官方源跑同一条路线做交叉比对。界面标签原文：「真实气象接口（Open-Meteo 公网实况）」

包内模拟数据（离线兜底）

断网或令牌失效时接管，标签同步变为「离线模拟」，不假装在线

频度合规闸门（禁止暴力访问）

结果缓存 10 min；每个数据源各自最小回源间隔 60 s；跨源最小间隔 5 s；同一源连续 3 次失败熔断静默 300 s。切源换不来免费额度

来源当场可核验（不是嘴上说说）

GET /api/weather/real 同时回传 selectedSource（用户选的源）与 servedSource（屏幕上这批数字真正来自哪个源）＋ servedFresh（是否本次取的）；GET /api/weather/rate-stats 回传真实回源次数 / 被节流拦截次数 / 熔断次数与逐源窗口。用户的选择与数据的实际来源是两件事，界面上分开写清，节流窗口内显示的是缓存就直说是缓存。

②风险引擎层气象有什么用 · 转成"能不能走"

实时气象联动判据（逐边取两端较差天气）

小时雨强 ≥ 50 mm/h → 惩罚 100（暴雨）；≥ 20 → 20；风速 ≥ 60 km/h → 50；能见度 < 100m → 50、< 500m → 20；气温 ≥ 35℃ → 8（冷链货损）。惩罚系数 ≥ 100 即判该边“等效道路中断”，算路时直接跳过

官方预报 / 沙盘判据（口岸断面）

断面取未来 6h 累计降雨：友谊关阈值随企业风险容忍度取保守 80 / 平衡 100 / 激进 120mm，芒街固定 70mm；达阈值即注入 penalty=100 参与算路，界面改档即全链路重估

恢复带滞后，不来回翻

80mm 熔断后需降到 75mm 以下才解除（阈值 − 5mm 滞后线）；降雨达 50mm 只进入“关注”态作叙事展示，不注入软惩罚——惩罚是乘数，乘上去会连口岸通关时间一起放大，方案时效就失真了

同一次降雨，为何只封友谊关

友谊关 85mm ≥ 80 → 越限熔断；芒街 62mm < 70 → 未越限可通行。逐边给出越限依据与触发源，不是一刀切

熔断后剩余图重算 + 全要素代价

毫秒级、可重复执行；输出里程 / 耗时 / 绕行延误 / 油耗 / 通行费 / 通关时效 / 货损金额 / 碳排放

创新点

公—水双向互备评估

公路熔断 → 即刻评估运河水运可执行性；水运禁航（能见度 < 1000m 等红线）→ 反向核算公路绕行成本

水运断面独立建模

运河每条支流按自身特征向量单独输出风险概率，不做全线一刀切；通航观测可由水运平台回传或模拟推送，回传后同样走②的阈值闸门与③的解释链

③AI 智能体层怎么与 AI 交互 · 引擎给边界，模型给文字

职责严格分离（本图最关键的一条线）

引擎 → 智能体：下传结构化熔断清单与决策边界（哪条边熔断、绕行代价、货损金额），作为提示上下文； 智能体 → 引擎：只回文字（风险解释、方案研判陈述、中越双语预警文案），模型生成的数字一律不采信，所有数值仍由确定性引擎产出。

三个智能体顺序接力

风险研判（为什么封友谊关不封芒街）→ 方案生成（对可比方案集做取舍建议）→ 协同触达（按角色出双语文案）

行业知识库提供依据

通航安全规定 / 跨境物流规范 / 企业作业规则，按标题、关键词、正文加权匹配，命中条目注入上下文，抑制无根据表述

推理通道逐级兜底且如实回报

本地大模型 → 企业内网网关 → 在线大模型 → 规则模板；结果面板标注本次真正走了哪一档，断网重试即变"规则模板"

任一通道不可用都不断流程

只影响文字表述，数值结果与推荐方案不变；预生成文案仅在缓存模式出现并单独标注

读图要点　七层是职责划分，带圈数字 ①→④ 才是本项目的主张：① 气象观测量从官方接口进来（且来源与频度都可当场核验）→ ② 被直接转换为路径可通行性（雨量越限即等效中断，不是把数字念给人听）→ ③ 大模型只负责解释与文案，数字全部由确定性引擎产出 → ④ 因此每一个调度动作都能回溯到具体雨量与阈值：换线绕行、局部绕行、改走水运、停驶等待、分级叫应，现场改档即可复算。 水运不作为并列第二主线，只在公路受阻时被触发评估，故以虚线框表示。本图只划分职责与数据流向，不体现具体框架选型； 接口清单见《01-技术文档》，带技术标注的展开版见《02-系统架构与数据使用说明》，气象→动作的横向因果链另见《08-系统架构图》。
