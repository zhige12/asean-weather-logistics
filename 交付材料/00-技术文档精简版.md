# 东盟天气敏感物流调度系统 · 技术文档（精简版）

> **摘要**　系统面向中国—东盟跨境物流，把台风、暴雨等强对流天气作为一等决策变量，贯通公路口岸通行与水运航道适航的实时联动调度，覆盖算路、在途、叫应与留痕全链路；决策过程可因果验证，并支持完全离线复现。

## 一、问题与定位

面向中国—东盟（以中越口岸为典型场景）的**天气敏感型跨境物流调度**。台风、暴雨等强对流天气会同时冲击公路口岸通行与水运航道适航。传统调度把天气当静态备注，本系统把天气作为**一等决策变量**，贯穿「算路 → 在途 → 叫应留痕」全链路实时联动。

典型链路：**南宁(NN) → 河内(HN)**，公路经**友谊关 / 芒街**口岸通关，水运经**平陆运河**出海。天气恶化时系统要连续回答：封不封关、停不停航、要不要换线、司机侧如何标红提醒、调度如何分级叫应并留痕。

## 二、系统架构总览

| 层 | 组成 | 职责 |
|---|---|---|
| 前端 | Vue3 调度大屏 + 司机端（Capacitor 瘦客户端 / Web） | 地图可视化、风险标红、语音叫应、任务同步 |
| 后端 | Spring Boot 4.1.0（REST，默认端口 8080） | 算路、风险引擎、气象代理、决策沙盘、留痕 |
| 数据 | 路网 / 口岸 / 气象观测 / 瓦片缓存 / 决策缓存 | 支撑离线可复现演示 |
| AI | 本地 Ollama + 在线 DeepSeek + 离线文案池（三级降级） | 态势解读、文案生成 |

**三智能体协同**：调度 Agent、司机 Agent、越南侧 Agent（`DRIVER_VN`），经实时事件与 `/api/agent`、`/api/agent/analysis` 联动，形成「口岸—车队—对方口岸」三方视角；实际编排在 `DecisionOrchestrator`（串行调度 + 预生成缓存 + `agent-status` 广播）。

## 三、业务全流程：五阶段闭环

系统把一次天气冲击的处理拆成对用户透明的五阶段服务闭环，每阶段都有明确的前台触点、后台算法与支撑系统：

| 阶段 | 用户动作 | 前台界面 | 后台支持 |
|---|---|---|---|
| ① 风险感知 | 收到风险预警 | 大屏熔断弹窗 / App 推送 | 气象注入 + `RouteService` 阶跃熔断 |
| ② 方案生成 | 查看六维方案对比 | AI 多维分析面板 | `RiskAgent→SolutionAgent→TouchAgent` |
| ③ 人工决策 | 调度员点选最终方案 | 决策沙盘滑块 + 选择按钮 | `DecisionSandboxService` 实时重估 |
| ④ 分级触达 | 各角色接收专属指令 | 司机端任务卡 / 语音播报 | SSE `/api/agent/events` 广播 |
| ⑤ 闭环确认 | 点击"确认/Xác nhận"回执 | 确认回执状态灯 | `TaskController /accept` + `DecisionLogService` 留痕 |

**分级叫应（三级递进）**：黄色关注→App 推送需点击确认；橙色准备→App＋短信需回复确认；红色立即行动→App＋语音外呼，未确认自动上报调度端并升级渠道。熔断计算对司机不可见、只显结果（可视分离线），决策权始终归属人。

**三条核心业务流**：公路熔断→评估运河可行→切陆水联运（推司机去港/船长备装/港口泊位）；运河能见度<1000m 禁航→反向评估公路绕行芒街（船长取消装船/司机改走公路/口岸预约）；拔网线后重复全流程，本地推理＋缓存数据，功能正常、数据不出境。

## 四、核心机制与创新点

### 4.1 天气 → 风险 → 算路熔断联动
风险引擎对路网边打惩罚分，超阈值即熔断改走。台风判定采用**气压 + 风速双条件**（`TyphoonRiskRule`）：仅当气压 ≤ 990hPa **且**风速达标才判台风，避免静风低压误触发。风阈值分档：40km/h 侧风预警、60km/h 高危、`IMPASSABLE_PENALTY=100` 为不可通行；真实侧风 ≥ 60km/h 判 HIGH、≥ 100km/h 判 CRITICAL。

### 4.2 陆水联运与禁航换线
平陆运河按风/雨顶穿红线时置 `waterBlocked`；公路段最大风速按 `/3.6` 折算灌入水运引擎，使公路与水运风险**同源联动**。口岸熔断（`roadBlocked`）触发时本程算路自动绕开；全域受阻时由 `CorridorAdvisoryService` 给出 DEFER/RETURN/HOLD 三种处置建议。

### 4.3 决策沙盘（可演示的因果）
`/api/sandbox` 提供 15 个接口，可手动调节气压/风速滑杆，实时观察熔断、改走、水运禁航、司机标红的连锁反应——把「黑箱决策」变成「可当场验证的因果链」。

### 4.4 分级叫应与留痕
`/api/outreach` 按风险等级触发语音/文字叫应并留存记录，形成闭环证据链。

## 五、后端模块结构

后端为单体重现工程（`src/main/java/com/example/aseanweatherlogistics`），经接口取证脚本统计，共 **23 个 REST 控制器、105 个端点**，统一由 `GlobalExceptionHandler` 产出带中文 `message` 的错误体。核心服务按职责分组：

| 分组 | 关键类 | 职责 |
|---|---|---|
| 算路与风险 | `RouteService`（邻接表 + A* + 逐边惩罚硬熔断）、`RouteAgentService`（300ms 防抖重算 + SSE 广播）、`TyphoonRiskRule`/`DriverRiskTipRule`/`RoadRiskIndex` | 边权惩罚、熔断改走、司机侧预警 |
| 多源气象 | `RealWeatherService`（节流 + 熔断）、`ContestWeatherProvider`/`OpenMeteoWeatherProvider`/`SimulatedWeatherProvider`、`WeatherWatchdogService`（60s 守护） | 官方→公网→模拟三级降级 |
| 三智能体 | `DecisionOrchestrator`（编排入口）、`RiskAgent`/`SolutionAgent`/`TouchAgent`、`RecommendationPool` | 态势解读、方案轮换 |
| 大模型通道 | `OllamaService`（本地）/`DeepseekService`（在线，前置**有界并发闸**）/`AIService`（降级）/`AiMetricsService`（计量与拒绝计数） | 三级 AI 降级 + 超上限快速失败降级 |
| 水运联运 | `WaterRiskEngine`（四条禁航红线）、`TributaryRiskService`、`IntermodalService` | 禁航判定、陆水切换 |
| 业务支撑 | `TaskService`、`TripSignalService`、`DecisionSandboxService`、`DecisionLogService`、`OutreachService` | 任务/在途/沙盘/留痕/叫应 |

**接口分布**：`/api/routes`(12)、`/api/sandbox`(15)、`/api/weather`(13)、`/api/v1`(4)、`/api/agent`(4+1)、`/api/task`+`/api/trip`(5+4)、`/api/canal`+`/api/waterway`(6+3)、`/api/outreach`(6)、`/api/ai`(5)、`/api/risk/model`(3)、`/api/customs`(5)、`/api/speech`(2)、`/api/copilot`(2)、`/api/ai/metrics`(1)，其余健康检查/静态资源若干。

## 七、地图与数据：离线可复现的根基

**自动降级链**保证任何网络条件下地图与气象都不白屏：

- **气象**：官方 CRA40 观测 → 公网 Open-Meteo → 内置模拟；界面如实标注当前真正服务的源（`selectedSource` 与 `servedSource` 分开回显，不假装官方）。
- **底图**：在线天地图（密钥仅存后端，前端走同源代理）→ 本地预热瓦片；未配密钥时 `/api/tianditu/**` 返回 503，前端自动降级。

包内预置 **z14 及以上约 1.4 万张**影像瓦片（两级「内存 + 磁盘」缓存），拔网线仍能出图，深层缩放才走实时回源。这是「离线演示」承诺的技术底座。

## 十、AI 能力与诚实降级

在线 DeepSeek 生成态势解读；无外网时自动降级到本地 Ollama，再降级到 `decision-cache` 离线文案池 + 规则模板。**任何降级都在界面标注来源**，不冒充实时 AI 结论。所有 AI 调用经唯一漏斗 `DeepseekService.chatWithChannel` 前置**有界并发闸**（`Semaphore`，默认上限 4、抢许可超时 2s 可 env 覆盖），超上限即**快速失败**返回降级信号（不排队挂死 Tomcat 线程），拒绝次数由 `AiMetricsService.recordRejection()` 计数并随 `GET /api/ai/metrics` 透出（`inFlightLimit`/`peakInFlight`/`rejected` + 本次 tokens/耗时），前端底部行常驻显示「峰值并发 x/上限 · 限流降级 n」。
