5.4 离线演示（拔网线）清单

  1. 提前 ollama pull qwen2.5:14b 并让 Ollama 随系统启动（OLLAMA_ENABLED=true）。
  2. 提前拉取一次气象数据 / 或切 weather.source=simulated。

  5. 断网后重复核心流程验证：本地推理、本地算路、本地瓦片全部可用；界面上的来源/通道徽标应如实变为「模拟降级 / 缓存 / 模板」而不是继续谎称实时。

事件与两端的适配关系（逐事件比对后端 SseEmitter.event().name(...) 与两端 addEventListener(...) 得出）：

事件后端广播位置调度大屏 App.vue司机端 DriverApp.vue
initRouteAgentService 连接建立时不监听（当前活动起终点由各端自行 POST /api/agent/register 确定，不依赖首帧）不监听（同上，另有 GET /api/task/current 兜底）
route-updateRouteAgentService 风险变化重算后（300 ms 防抖）✓ 刷路线与风险着色✓ 刷导航与换线弹窗
task-assignedTaskController 派单后✓ 任务卡状态✓ 进任务模式
agent-statusDecisionOrchestrator 逐智能体点亮✓ 三智能体面板— 司机端不展示推理过程，按设计不监听
outreach-updateOutreachService 分级叫应状态变化✓ 触达进度的时间线✓ 指令弹窗
canal-block / canal-recoverDecisionSandboxService 禁航判定与解除✓ 水运层禁航态✓ 司机端禁航提示与换路

结论：除 init 为预留帧外，六类业务事件在「后端广播 ↔ 两端监听」两侧名称与语义完全一致，无孤立事件、无未接事件。

  • controller/ 19 个 REST 控制器（对应第六节 96 个端点）+ GlobalExceptionHandler（统一中文错误体）

  • 大模型通道：OllamaService（本地）/DeepseekService（在线）/AIService（预警文案与降级）、AgentJson（输出解析）
  • 代价与方案：CostCalculator、IntermodalService、DemoConfigService（企业画像/阈值档）、StartupWarmup
  • 水运：WaterRiskEngine（四条禁航红线）、TributaryRiskService、waterway/（WaterwayDataService + Mock/Official 双数据源）
  • 业务支撑：TaskService（NONE/DISPATCHED/ACCEPTED/REJECTED）、TripSignalService（在途进度与新鲜度）、DecisionSandboxService（沙盘状态机与方向判定）、DecisionLogService（留痕）、OutreachService（分级叫应）、CustomsEfficiencyService、KnowledgeBaseService、GeocodeService、BriefingService
  • repository/ RouteRepository/CustomsEfficiencyRepository/KnowledgeBaseRepository（JSON 载入）
  • model/ dto（RouteRequest/RouteResponse/RiskSegment/TransportTask）、entity（RoadNode/RoadEdge/KnowledgeEntry）、vo（WarningVO）
  • util/ GeoUtils（球面距离）、HttpUtil、DemoClock（装船/到达等时刻基于真实时钟推导，不写死）

三条结论：

  1. 主流程不需要任何凭证与外网：路网拓扑、地名库、知识库、瓦片缓存、决策预生成缓存均随仓库或交付包分发，断网机器上算路、风险判定、禁航、分级叫应、司机端触达链路可完整跑通。

``bash git grep -n -E "(TOKEN|_KEY|KEYS|_TK)[=:][0-9a-zA-Z]{8}" git grep -n -E "sk-[0-9a-f]{16,}" ``
